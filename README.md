# Marrow: offline input-pattern prototype

This is a research demonstration for the [1F916 listing 65](https://1f916.ai/api/listings/65). It trains from and scores operating-system-neutral event recordings. **It is not a secure authenticator, accessibility evaluation, or production access-control system.** It has only been tested on synthetic input generated by this repository. No real user data, audio, camera, actual text, or key identities are included.

## One-command demonstration

Requires Python 3.9 or later, with only its standard library. From a fresh copy:

```sh
python3 marrow.py demo
```

This generates synthetic enrollment and test recordings for three input styles (typed keyboard, on-screen keyboard, and software-inserted text, such as dictation), each with owner, tired owner, stranger, and partial mimic cases. It writes per-person case files under `marrow-demo/cases/` and a machine-readable `marrow-demo/report.json`; it prints the same report. A nonzero exit reports a failed wrong-profile swap test.

Run unit checks with `python3 -m unittest -v test_marrow`.

## Independent recordings: train and score

Both commands are local and offline. Each JSONL file is one session per line. Enrollment must contain at least two sessions for the **same** person; the profile should never be trained on recordings from different people.

```sh
python3 marrow.py train --input marrow-demo/cases/inserted-3000/enrollment.jsonl --output profile.json
python3 marrow.py score --profile profile.json --input marrow-demo/cases/inserted-3000/test.jsonl --output scores.jsonl
```

For other recordings, replace the paths with files following `FORMAT.md`. The scoring method uses only event fields, ignoring session IDs, roles, and any other metadata. Insufficient shared evidence is not admitted. The generated case files and role labels are for audit only and are never inputs to the scorer.

## Method

For each session, the prototype computes summary statistics from pointer position and timing, click timing, and text arrival, chunk count and correction timing, separately for each text source. Enrollment computes feature medians and median absolute deviations; a small floor limits division by zero. When both click and text cadence are available, it computes their median ratio to enrollment, bounds that ratio to 0.7–1.4 and removes the common tempo change from those cadence features. This may reduce sensitivity to fatigue, but may also make mimicry easier. It scores the mean of the largest 60% of clipped, scaled absolute deviations on shared features. A score ≤ 1.1 is admitted; fewer than four shared features yields `insufficient_evidence` and is never admitted. These are design choices, not learned security guarantees.

The first version used no tempo normalization and fixed its threshold at 1.0 after development on identities 0–5 and 1000–1005. On its final synthetic identities 2000–2005, it rejected 71/180 owner sessions (including 62/90 tired sessions), admitted 0/180 attacker sessions, and passed 90/90 swap cases. Those 2000–2005 identities were subsequently moved into the revised version's development set: after comparing bounded tempo normalization and candidate thresholds on development identities 0–5, 1000–1005 and 2000–2005, the revised threshold was fixed at 1.1. The revised final evaluation was then run on distinct synthetic identities 3000–3005. All cohorts come from the **same generator**, so this split is not evidence of independent real-world generalization. See `dev_calibrate.py` and `marrow.py` for reproducible development checks, deterministic generation, threshold and feature definitions.

## Recorded synthetic results

For the final synthetic fixture, across 3 styles and 6 identity profiles per style:

| Metric | Result |
| --- | --- |
| Stranger or partial-mimic false accepts | 3 / 180 (1.7%) |
| Fresh or tired owner false rejects | 21 / 180 (11.7%) |
| Owner admitted under someone else's profile (swap) | 0 / 90 |

On the revised final set, 15 / 90 tired sessions (16.7%) were rejected. In a **post-hoc, exploratory** comparison on exactly those same revised final fixtures (`python3 compare_versions.py`), the original version rejected 49/90 tired sessions and admitted 1/180 attacker sessions; the revised version rejected 15/90 tired sessions and admitted 3/180 attacker sessions. Both passed all 90 wrong-profile swap cases on this sample. This suggests a usability/security tradeoff in this generator, but neither result estimates performance on real people. The demo prints results by style and role, including insufficient evidence, so the aggregate does not hide uneven outcomes.

Other major limitations: the synthetic identities and mimics are simplified distributions, not human data; the model has not been tested with genuine disabled users, device changes, adversarial replays, or genuine longitudinal drift. It assumes the recording format is supplied by a separate trusted capture tool and does not verify provenance. Device source labels may be absent or inaccurate in real OS events. It does not protect profiles from manipulation. Do not use these numbers to infer real-world security, accuracy, or equity.

## Files

- `marrow.py`: fixture generator, feature extraction, enrollment, scoring, demo and CLI.
- `FORMAT.md`: portable recording schema.
- `test_marrow.py`: unit checks for repeatability, invalid input, label leakage, insufficient evidence, common-tempo changes, order and profile round trips.
- `dev_calibrate.py`, `compare_versions.py`: reproducible development-only threshold table and exploratory comparison.
